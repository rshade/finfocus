# Implementation Plan: Config Routes CLI Commands

**Branch**: `604-config-routes-cli` | **Date**: 2026-02-28 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/604-config-routes-cli/spec.md`

## Summary

Add `config routes list` and `config routes test` CLI subcommands to provide
visibility into the plugin routing configuration. The list command displays
routing rules in a formatted table showing priority, features, patterns, and
fallback status. The test command simulates plugin selection for a given
resource type, showing the full match chain and per-feature assignments.
Both commands support `--output json` for scripting. Implementation reuses the
existing `router.DefaultRouter.SelectPlugins()` method with synthetic plugin
clients constructed from config, ensuring the test output exactly mirrors
runtime behavior.

## Key Implementation Details

### Command Registration

Add `NewConfigRoutesCmd()` to `newConfigCmd()` in `root.go`:

```go
cmd.AddCommand(
    NewConfigInitCmd(), NewConfigSetCmd(), NewConfigGetCmd(),
    NewConfigListCmd(), NewConfigValidateCmd(), NewConfigRoutesCmd(),
)
```

### Output Flag

Use `--output` flag (not `--format`) with default `"table"`, matching the
convention used by `plugin list`, `analyzer check`, and other table-output
commands. Reuse existing constants `outputFormatTable` and `outputFormatJSON`.

### Synthetic Client Construction

For `config routes test`, construct synthetic `pluginhost.Client` instances
from config plugin names (same pattern as `config_validate.go` fallback):

```go
clients := make([]*pluginhost.Client, 0, len(cfg.Routing.Plugins))
for _, p := range cfg.Routing.Plugins {
    clients = append(clients, &pluginhost.Client{
        Name: p.Name,
        Metadata: &proto.PluginMetadata{
            SupportedProviders: []string{}, // empty = global provider
        },
    })
}
```

For proper automatic provider matching simulation, plugin metadata
should reflect the configured patterns' implied providers where possible.

### Router Integration

Create a `DefaultRouter` with `WithConfig` and `WithClients`, then call
`SelectPlugins()` for each feature. The router handles all matching logic
(patterns, provider extraction, region matching, priority sorting).

### Config Source Detection

Determine config source by checking `config.GetResolvedProjectDir()`:

- If non-empty and a project config exists: source = "project"
- Otherwise: source = "global"

Display the path via `cfg.ConfigPath()`.

### Priority Display

Higher number = higher priority (sorted first). This matches the router's
`sortByPriority` implementation (descending sort).
