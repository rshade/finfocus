# Implementation Plan: Resource History Store

**Branch**: `608-resource-history-store` | **Date**: 2026-03-30 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/608-resource-history-store/spec.md`

## Summary

Resource physical IDs (cloud IDs) change when infrastructure resources are
replaced, and resources may be created or destroyed mid-month. The current
`cost actual` implementation only knows about the current state snapshot,
causing systematic under-reporting of actual costs. This feature adds a
persistent BoltDB-backed history store that tracks all cloud IDs a resource has
ever had, enabling full-month cost accuracy across resource replacements and
deletions. The implementation follows the established BoltDB patterns from
`internal/engine/cache/store.go` with three write paths (state snapshot, plan
lineage, analyzer events) and one enhanced read path (actual cost queries).

## Technical Context

**Language/Version**: Go 1.25.8 (see `go.mod`)
**Primary Dependencies**: BoltDB (`go.etcd.io/bbolt` — already in `go.mod`),
Cobra, zerolog
**Storage**: BoltDB at `~/.finfocus/history/history.db` (separate from cache)
**Testing**: `go test` + testify (`require`/`assert`), table-driven tests
**Target Platform**: Linux (amd64, arm64), macOS (amd64, arm64), Windows
(amd64)
**Project Type**: Single Go project (CLI tool)
**Performance Goals**: History operations add ≤200ms overhead for up to 500
resources (SC-007)
**Constraints**: Commands must work without history store (constitution
Persistence Model); graceful corruption recovery; no cross-repo changes for
Layer 1
**Scale/Scope**: Typical stacks have 10-500 resources; history entries
accumulate over 90-day retention window; ~50,000 entries maximum per stack

## Research Findings (Phase 0)

See [research.md](research.md) for full details. Key decisions:

1. **BoltDB backend** — reuse existing dependency and patterns from cache store
2. **PulumiState.ID gap** — add `ID string` field to map the JSON `id` field
   (one-line change)
3. **Separate history.db** — distinct from cache.db per constitution v1.7.0
4. **SHA-256 key hashing** — fixed-length keys for efficient B-tree lookups
5. **HistoryStore interface** — follows cache.Cache pattern with WithHistory()
   injection
6. **Write path ordering** — state snapshot first (most impactful), then plan
   lineage, then analyzer events
7. **Layer 2 deferred** — tag-based allocation config defined but query logic
   is a separate milestone. Spec requirements FR-009/FR-010 are partially
   covered (config only); a follow-up issue must track the tag query
   implementation
8. **Startup cleanup** — retention runs on startup, same as cache expired
   entry cleanup
9. **BoltDB MVCC** — concurrent reads + serialized writes with 500ms lock
   timeout
10. **Fire-and-forget writes** — history write failures log warnings, never
    block main operations

### Data Flow Diagrams

**Write Path: State Snapshot**

```text
finfocus cost actual / overview
    │
    ├─ loadActualResources() / LoadStackExportWithContext()
    │   └─ Returns []ResourceDescriptor with pulumi:cloudId in Properties
    │
    ├─ [NEW] historyWriter.RecordStateSnapshot(stackCtx, resources)
    │   └─ For each resource: Upsert(URN, cloudID, type, provider, tags)
    │   └─ Fire-and-forget: log warning on error, never block
    │
    └─ Continue with normal cost query flow
```

**Write Path: Plan Lineage**

```text
finfocus overview
    │
    ├─ pulumi preview --json
    │   └─ Returns PulumiStep[] including replace/delete ops
    │
    ├─ [MODIFIED] extractResources()
    │   └─ Now processes replace/delete ops too
    │   └─ Extracts OldState.ID and NewState.ID
    │
    ├─ [NEW] historyWriter.RecordPlanLineage(stackCtx, steps)
    │   └─ For replace: Upsert old cloudID + Upsert new cloudID
    │   └─ For delete: Upsert old cloudID with current timestamp
    │
    └─ Continue with normal overview flow
```

**Read Path: Enhanced Actual Cost Query**

```text
finfocus cost actual --from 03-01 --to 03-31
    │
    ├─ loadActualResources()
    │   └─ Returns current state resources
    │
    ├─ [NEW] historyReader.GetResourcesForPeriod(stackCtx, from, to)
    │   └─ For each URN: get ALL cloudIDs active in [from, to]
    │   └─ Also returns deleted resources active in [from, to]
    │
    ├─ [NEW] Merge: create one ResourceDescriptor per historical cloudID
    │   └─ Replaced resource → 2 ResourceDescriptors (old ID + new ID)
    │   └─ Deleted resource → 1 ResourceDescriptor (historical ID)
    │   └─ Deduplication: skip cloud IDs already in current state
    │
    ├─ Engine.GetActualCostWithOptions()
    │   └─ Unchanged — processes each ResourceDescriptor with its single cloudID
    │   └─ Engine/adapter pipeline handles one ID per resource as before
    │
    └─ Aggregate and return
```
